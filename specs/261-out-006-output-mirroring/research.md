# Research: OUT-006 Output Mirroring Toggle

- **OUT-006-D1 Interpretation.** Decision: "same scene vs clean output variant" is a choice of which layer classes reach the external output (Same scene: visual + scene overlays; Clean: visual only); the interface never reaches it. Rationale: OUT-001 renders once and moves the one visual view between windows (OUT-001-R3); the device's controls, HUD, guides and performance overlay are already SwiftUI in the device window. Alternatives: a device-side live mirror while the display also shows the visual — needs a second presentation of every visual (a per-frame GPU copy in five Metal hosts plus the ANGLE engine, which has no frame tap), against OUT-001-R3; public APIs cannot show one layer in two windows. Snapshot-based previews (`snapshotView`) are static and cost a render-server copy per update. Rejected.
- **OUT-006-D2 How overlays are left out.** Decision: the logo layer stays attached; `LogoCoordinator` pushes an effective placement with opacity 0 while overlays are routed away (MED-010: opacity 0 draws nothing, the picture stays clear) and the stored placement otherwise. Rationale: no reload, no stack change, so switching is next-frame and allocation-free; the stored placement (scenes, backup) is never touched. Alternatives: removing the layer from each compositor stack (re-applies stacks, reloads the picture); layer mute (CMP solo/mute is the user's layer-inspector state).
- **OUT-006-D3 Where the rule is evaluated.** Decision: `ExternalDisplayCoordinator.place()` (every routing change: connect, settle, disconnect, hold, visual change) and the `outputMode` setter compute `OutputLayerRouting.routesSceneOverlays(target: effectiveTarget, mode:)` and call `onSceneOverlaysChange` only when it changes. Rationale: one place already decides where the visual is.
- **OUT-006-D4 One stored mode.** Decision: one device-local key for the external output; device always Same scene. Rationale: one external display shows the visual at a time; scene identifiers do not identify hardware.
- **OUT-006-D5 Recording hold.** Decision: applies live (spec clarification). The recording records the one output.
- **OUT-006-D6 Proof of one capture.** Decision: the app acceptance test builds a real `AppCoordinator` (test defaults suite, its own `ExternalDisplayCoordinator`), records the identities of `manager`, `manager.normalizedOutput` and `manager.analysisTap`, the manager's state and transition count and the session's start count, toggles the mode with the stand-in display attached, and asserts all unchanged; plus the external slot holds exactly the visual view in both modes.
