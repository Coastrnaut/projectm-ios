# Research: OUT-005 Safe-Area Guides

- **OUT-005-D1 Percentages.** Decision: SMPTE ST 2046-1 (2009) values, action-safe 93 % and title-safe 90 % of width and height, centred; configurable 80…100 % and 70…100 % in whole percent. Rationale: current HD/UHD convention; the legacy analogue 90/80 values are still reachable. Alternatives: 90/80 defaults (too conservative for flat panels and projectors); separate horizontal and vertical percentages (more controls, no stage need).
- **OUT-005-D2 Isolation.** Decision: a SwiftUI overlay in the visualizer's backdrop above the visual, never inside the visual's view or the compositor. Rationale: OUT-001 moves only the visual's own view to the external window; recordings and Save Frame read the visual's drawable (frame-capture tap), not the window. UIX-013's `SceneHUDAppTests` already proves this pattern pixel-identical. Alternatives: a compositor layer flagged "editor only" (would need every output path to filter it; risk of leaks).
- **OUT-005-D3 Output frame.** Decision: device visual area when the device shows the visual; when an external display shows it, the display's physical aspect (points width × resolved pixel aspect ÷ height) fitted and centred. Rationale: safe areas belong to the screen the audience sees; OUT-004's pixel aspect makes the shape physical. Alternatives: map the external crop (Fill) back onto the device picture — the device does not show the picture while it is external (OUT-001-R2), so there is nothing to map onto.
- **OUT-005-D4 Split editor.** Decision: the overlay takes `.splitOutputScaled()` with the visual, so it is drawn over the scaled output in UIX-007's pane.
- **OUT-005-D5 Probe.** Decision: DEBUG `-uitestDiagnostics` only, an almost transparent text `safeAreaGuidesProbe` whose value is "action=<p> title=<p> cross=<yes|no> frame=<W>x<H>"; the guides themselves stay hidden from accessibility.
