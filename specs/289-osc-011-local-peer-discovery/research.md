# Research: OSC-011 Local Peer Discovery

- **OSC-011-D1 Discovery mechanism.** Decision: Bonjour via Network.framework (`NWBrowser` with `.bonjour(type: "_projectm-osc._udp", domain: "local.")`; announcing with `NWListener.service`). Rationale: multicast DNS on the local link needs no server or relay and is the public iOS API; iOS requires the type in `NSBonjourServices` and gates it with the Local Network permission the app already asks for. Alternatives: `NSNetService` (deprecated, and rejected by the symbol scan), `DNSServiceBrowse` (C API, rejected by the scan), MultipeerConnectivity (peer-to-peer Wi-Fi and Bluetooth, forbidden library), a rendezvous server (a relay: forbidden).
- **OSC-011-D2 Announce on the receiver's listener.** Decision: set `NWListener.service` on OSC-001's listener instead of a second listener. Rationale: Bonjour advertises the listener's own port, so only the receiver's listener can announce the real OSC port; it ends with the listener (OSC off, background) for free. Setting `service` after start updates the registration (Network.framework re-registers; checked by the host loopback test). Alternatives: a second listener on the same port with port reuse (unicast delivery to two sockets is unpredictable), a second port in a TXT record (an extra open port).
- **OSC-011-D3 Resolving a found service.** Decision: a UDP `NWConnection(to: result.endpoint)` that is started, read once for `currentPath.remoteEndpoint` when ready, and cancelled; it sends nothing. IPv4 is required on the resolution parameters (`NWProtocolIP.Options.version = .v4`), so the address is usable as an OSC-005 destination; a peer is shown only when the address passes `OSCPeerAddress.isLocal`. Resolution times out after 5 s (then "Resolving…" stays and no action is offered). Alternatives: `NWBrowser.Result` metadata (has no address), TXT-record addresses (spoofable, interface-dependent).
- **OSC-011-D4 Parameters.** Decision: `includePeerToPeer = false`, cellular prohibited, domain `local.` only. Rationale: local link only, as the receiver.
- **OSC-011-D5 Announced name.** Decision: "projectM " + 4 uppercase hex digits from the system random generator, per launch, memory only. Rationale: no device or user name leaves the device; a per-launch value is not a stable identifier. Own announcement is filtered by name.
- **OSC-011-D6 Two switches.** Decision: separate "Find nearby devices" and "Let nearby devices find this one"; keys `settings.osc.discovery.browse` and `settings.osc.discovery.advertise`, absent → off, device only (like OSC-008).
- **OSC-011-D7 Symbol scan.** Decision: marker `NetworkOSCPeerBrowser`; `NWBrowser*`, `NWListener.Service*`, `NWListener.service`, `NWConnection.init(to:using:)`, `NWConnection.currentPath`, `NWPath*` (remote endpoint) and `NWProtocolIP*` pass only in an image that defines it (and the OSC transport); `NWListener.Service`/`service` are taken out of the generic listener-side allow. ADR-0100.
- **OSC-011-D8 Source scan.** Decision: `check_compliance.py` requires that `NWBrowser` and `NWListener.Service` appear only in the two reviewed files, that the only Bonjour type string anywhere in Swift sources and `NSBonjourServices` is `_projectm-osc._udp`, and that the discovery file contains no `URLSession`, no `NWEndpoint.Host("…")` / `.name(` host names and no `.hostPort(` construction.
- **OSC-011-D9 Loopback test.** Decision: a host test announces through a real `NetworkDatagramTransport` and browses with `NetworkOSCPeerBrowser`; it expects its own service (own-name filter off) within 5 s and skips (XCTSkip) if the host's mDNS gives nothing, so it never fails flakily; the device test is `{device}`.
