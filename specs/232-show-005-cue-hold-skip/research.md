# Research: SHOW-005 Cue Hold and Skip

- **SHOW-005-D1 — Hold is one more SHOW-002 hold source.** Decision: OR the performer's Hold into the existing hold check in `ShowAutoAdvanceCoordinator`; the timeline already keeps the remaining time and starts new cues held. Alternatives: a separate "automation off" flag that cancels the countdown (loses the remaining time; the acceptance wants a resume) — rejected.
- **SHOW-005-D2 — Hold is session state.** Decision: not stored (no UserDefaults key, not in `show.json`). Rationale: a show that silently refuses to advance after a relaunch is the worse failure; matches pause, which is not stored either. Alternative: a stored setting (needs FILE-005 policy, erase and UI-test reset entries) — rejected.
- **SHOW-005-D3 — A timed step already waiting for the beat.** Decision: Hold withdraws it (only when it is timed; a manual step waiting stays) and re-arms the timeline held with zero remaining, so Hold off requests it again at once. Rationale: "Hold prevents automatic advances" must hold within the bar, and nothing is lost. Alternative: let it land (up to one bar later) — rejected.
- **SHOW-005-D4 — Skip in the pure list.** Decision: `next`/`previous`/`canGo*` skip in `ShowCueList`, so every source (controls, keys, pad, MIDI, OSC, timed, quantized preview) gets it from one place. `go(to:)` stays explicit. A new outcome `.allSkipped` (no exhaustive switch on `ShowStepOutcome` exists in the app).
- **SHOW-005-D5 — File field.** Decision: optional `skip` boolean per cue, written only when true; lenient read (`StoredSkip`); warning `droppedSkipFlags(Int)`; no version bump (SHOW-002/004 pattern).
- **SHOW-005-D6 — Countdown after a Skip edit.** Decision: `listChanged` cancels the countdown when the active cue has no next cue any more; unskipping never starts one (edits do not start automation; the next step does).
- **SHOW-005-D7 — Pad.** Decision: no fifth target (UIX-005's layout is sized for four); the readout shows "Hold" and carries a VoiceOver action; the visible toggle lives in the cue row.
- **SHOW-005-D8 — Swipe edge.** Decision: Skip on the trailing swipe next to Delete. Rationale: the leading row is wider than an iPhone (measured: a seventh action at x = 475 of 402 points, not hittable). Alternatives: a leading action (cut off), first in the leading row (pushes Transition and Into, which SCN-007 and SHOW-004 UI tests tap, off screen), the context menu only (slow to settle over the live visualizer: 60 s idle waits in the UI test) — rejected.
