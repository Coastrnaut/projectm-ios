# Research: VIS-008 Particle Fountain

- **VIS-008-D1 Onset input.** ANL-004 publishes `AnalysisEventKind.onset(strength:threshold:)` on ANL-016's bus (strength is the frame's spectral-flux detection value 0…1; the threshold is δ + κ·mean of the preceding window, δ = 0.06, so thresholds are ≥ 0.06; onsets are at least 50 ms apart). The native host already subscribes while VIS-006's beat rings are shown and drains the subscription each frame (`nextEvent`, a value copy). The fountain extends that subscription to its own style; `ParticleFountainTrigger` maps `onset` events to (strength, threshold) and ignores every other kind. Each onset is stamped with the frame's time (as VIS-006's rings): the bus time is the analysis window's end, already in the past when drained.
- **VIS-008-D2 Burst size.** The excess over the threshold, not the raw strength, measures how strong the onset is relative to its context. e = clamp((s − θ)/0.25, 0, 1); n = 4 + round(20e). At the detector's highest rate (20 per second) with 24-particle bursts and 2.5 s lifetimes the demand (1,200) exceeds the pool (512): bursts are truncated, never older particles replaced, so the count stays bounded and in-flight motion stays smooth.
- **VIS-008-D3 Deterministic stepping.** Step k starts at t_k = anchor + ⌊k·10⁹/240⌋ ns (Int64 arithmetic, exact), so the schedule is the same however frames arrive. `advance(toNanoseconds:)` runs every step with t_{k+1} ≤ target; before step k it spawns every queued onset with time ≤ t_k (FIFO, so spawn order and the PRNG draws are fixed). An onset is always enqueued before the simulation passes its time (its stamp is the current frame time, ≥ the simulation's time), so chunking cannot change which step spawns it. A gap longer than 240 steps skips the rest and moves the anchor (frames stay bounded after a stall; documented, not exercised by the acceptance).
- **VIS-008-D4 Integration.** Semi-implicit Euler: v ← v + (g − k·v)Δt; p ← p + vΔt; age ← age + Δt. Without drag, after n steps p_y = v₀n·Δt − g·Δt²·n(n+1)/2: the test checks this closed form within 1e-9. With drag, a rising particle's speed decreases monotonically (both terms oppose the motion).
- **VIS-008-D5 PRNG.** SplitMix64 (state += 0x9E3779B97F4A7C15, then two xor-shift-multiplies): a pure 64-bit integer function, identical on every platform; `unit()` = (x >> 11) × 2⁻⁵³. Two draws per particle (angle, speed). Seed restored at every loop restart, so a restart replays the same sequence for the same onsets.
- **VIS-008-D6 Reduce Motion.** Time scale σ = 0.7: v₀·σ, g·σ², k·σ, life/σ. In continuous time this traces the same path at σ times the speed; with the fixed step it is within discretization error (apex within 1%). Captured per particle at spawn (gravity and drag stored with the particle), so toggling changes only later bursts; the Gravity setting likewise.
- **VIS-008-D7 Flash model.** Each live particle is an axis-aligned square (convex): `SpectrumFlashAreas` clips it to the 4 × 4 tiles. Overlapping squares count twice (an overestimate, as VIS-006's overlapping rings). Alpha 0.8 × attack ramp × linear fade; the 50 ms attack avoids a hard step on a burst; FX-019's gain bounds the rest.
- **VIS-008-D8 Golden.** Seed 0x5EED0008, Medium gravity, onsets at t = 0 (strength 0.5, threshold 0.1) and t = 0.25 s (0.35, 0.1), rendered at t = 0.6 s after advancing from t = 0 with 60 Hz frames; glow off, Reduce flashing off; both golden resolutions. Particle positions are in R units, so both resolutions show the same picture scaled.
