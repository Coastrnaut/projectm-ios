# Tasks: AUD-006 Seekable transport

**Input**: Design documents in `specs/007-aud-006-seekable-transport/` (spec.md, plan.md,
research.md, data-model.md, contracts/, quickstart.md)

**Tests**: test-first. Each test task comes before the code it covers; the red run (compile
failure or failing assertions) is recorded in AUD-006-T12 before any production change.

**Format**: `- [ ] ID [P?] [Story?] Description with file path`. `[P]` = can run in parallel
(different files). Tags: `{device}` = needs a physical device, done only in the roadmap's final
device phase; `{sim}` = needs the iOS 27.2 simulator (udid
`77E17861-E687-4274-8A84-14224F32BE3E`, "iPhone Air").

A task is ticked only when its acceptance evidence was produced, with
" — Verified <date>: <how>" appended.

Inside task descriptions, "T07" is short for `AUD-006-T07`. Phase (Constitution, Workflow): all
tasks belong to the roadmap's AUD area, after AUD-001 and AUD-002. Every task needs macOS with
Xcode except AUD-006-T36 (any OS); only `{device}` tasks need a physical device. The app builds in
the feature worktree with the 28 included presets; two app tests that need the full preset library
(`PresetTests.testBundledIncludedScopeMatchesRelease1_0`, `VisualizerUITests.testPresetBrowser`)
are known to fail there and are not evidence for or against this feature.

## Implementation strategy

MVP is Phases 1 to 3 (seek through the whole pipeline with the acceptance test). Phases 4 and 5
complete the transport model; Phase 6 puts it on screen; Phase 7 verifies everything twice.
