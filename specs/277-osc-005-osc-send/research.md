# Research: OSC-005 OSC Send

- **OSC-005-D1 Transport**: Decision: one UDP `NWConnection(host: .ipv4/.ipv6(literal), port:, using: .udp)` with `prohibitedInterfaceTypes = [.cellular]`, on a private serial queue. Rationale: the receiver already uses Network.framework in `OSCTransport/`; a literal `NWEndpoint.Host` never triggers DNS. Alternatives: BSD sockets (forbidden by FR-068 and the symbol scan); `NWConnectionGroup` (multicast, out of scope).
- **OSC-005-D2 Host names**: Decision: refused. Rationale: resolving a name is a DNS query (`check_network_symbols` and the constitution forbid resolvers), and `.local` names would need Bonjour (OSC-011). Alternatives: allow `.local` names (rejected: discovery is OSC-011's row).
- **OSC-005-D3 Local rule**: Decision: reuse `OSCPeerAddress.isLocal` and additionally refuse IPv6 link-local (no zone field), 0.0.0.0/8 and `::`, multicast (224/4, ff00::/8) and 255.255.255.255 (already non-local except the private-range directed broadcasts, which the app cannot detect without the netmask and which `NWConnection` UDP rejects without the broadcast option). The transport re-checks `isLocal` before opening.
- **OSC-005-D4 Disable semantics**: Decision: `close()` increments a generation under a `Mutex` synchronously, so any send block already queued but not run is dropped; then the connection is cancelled on its queue. The sender stops creating messages at once (its own `active` flag under its lock). In-flight sends are capped at 16 so a connection stuck in `waiting` cannot grow memory.
- **OSC-005-D5 Rate cap**: Decision: an exact sliding window of the last 60 send times (ring buffer) on `OSCMonotonicClock`; a message is admitted when fewer than 60 were sent in the past 1 s. Excess is dropped and counted, never queued (a queue would delay a later disable and keep stale beats). Alternative: token bucket (OSC-009 style) — allows bursts above 60 in a window edge case.
- **OSC-005-D6 Beats**: Decision: a pure `OSCBeatGate` takes the tempo grid (anchor, period) and `now`; the beat index is `floor((now − anchor) / period)`; a beat message is produced when the index differs from the last seen index and at least 250 ms passed since the last beat message; the first observation only records the index. The app polls every 50 ms while sending is active and beats are on. Rationale: TempoSnapshot has no event stream for consumers; `analysisEventObserver` is a single slot owned by ACC-007 haptics. Alternatives: hooking the analysis event observer (would steal haptics' slot; would miss manual and MIDI clock tempos).
- **OSC-005-D7 Address namespace**: `/projectm/scene`, `/projectm/beat`, `/projectm/status`, documented in the contract. These are not routes of the receiver, so a loop back into the app's own receiver is ignored (counted as unknown).
- **OSC-005-D8 Compliance**: `check_compliance.py` already allows the whole `OSCTransport/` folder (no change). `check_network_symbols.py` allowed outbound `NWConnection.init(host:port:using:)`/`send` only beside the DEBUG `OSCLoopbackSender` and `--release` rejected that sender: a reviewed sender marker `NetworkOSCSender` now allows those APIs in its image, also in Release (ADR-0088). The DEBUG loopback sender rule stays.
- **OSC-005-D9 Loopback fixture in app tests**: test targets may not import Network (the compliance scan covers tests), so the app test uses the package's public `NetworkDatagramTransport` as the listener on port 0 (system-chosen free port) on 127.0.0.1.
