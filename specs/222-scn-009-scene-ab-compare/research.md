# Research: SCN-009 Scene A/B Compare

- **SCN-009-D1 Where saving stops.** Decision: suspend SCN-002's autosave and SCN-010's history for the session (each gets `suspend()`/`resume`), rather than snapshotting and rewriting files afterwards. While suspended the autosave keeps observing (so its observation stays armed) but notes no edit and commits nothing on any trigger (debounce, `commitNow`, background, `flushSynchronously`); the history captures nothing and refuses undo/redo. Rationale: the files are never touched, so byte identity holds by construction and a kill at any moment leaves the pre-Compare scene (R9) for the existing restore path. Alternatives: write and roll back (rejected: a crash between write and rollback saves the preview); a separate "preview" scene file (rejected: a new file and restore path for no gain).
- **SCN-009-D2 Exact resume.** Decision: starting first commits a pending edit synchronously (`flushSynchronously`) and closes history coalescing, then captures the pre-Compare `SceneInputs`. `resume(from:)` re-arms the autosave against those inputs: if the live inputs differ (Keep, or a cue during Compare) it notes one edit under the normal rules; if equal (Cancel) nothing is pending. Rationale: the autosave sees exactly the change since before Compare, no more and no less.
- **SCN-009-D3 The switch is a cut.** Decision: values are written through `SceneSnapshotCoordinator.write` (the Settings targets; MOD-017-D8 keeps recall paths immediate), only where they differ; no CMP-014 crossfade (that bus blends cue outputs, not parameters) and no quantize. Rationale: "switch instantly".
- **SCN-009-D4 Side state.** Decision: pre-Compare values overlaid with the snapshot's `SceneSnapshotRecallPlan.writes`; skipped values (unknown or unsettable) keep the pre-Compare value. Rationale: toggling A→B→A must land on identical values even when the snapshots hold different sets.
- **SCN-009-D5 Cancel path.** Decision: `SceneHistoryCoordinator.apply` (AppCoordinator's `applySceneInputs`, the undo path) with the pre-Compare inputs, then the parameter values through the targets where they still differ. Rationale: restores edits made beside the output too (Clarifications), on a path already tested by undo.
- **SCN-009-D6 Lock.** Decision: start, toggle and Keep call `SceneLock.refusesEdit()` first; Cancel does not (it returns to the saved scene). Rationale: the switch writes the targets the lock guards (SCN-015-D1); a locked show is not changed by a preview.
- **SCN-009-D7 Abandon on restart.** Decision: `SceneHistoryCoordinator.restart()` while suspended calls the compare coordinator's `abandon()` before beginning again; it resumes both against the pre-Compare inputs without restoring. Rationale: one hook covers cues, Reopen and photo/video replacement (all call `restart`).
- **SCN-009-D8 Announcements.** Library lane (ACC-004), like snapshot messages.
