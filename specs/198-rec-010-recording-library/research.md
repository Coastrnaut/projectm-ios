# Research: REC-010 Recording library

- **REC-010-D1 Keep, not auto-keep.** Decision: a Keep action on the "Recording ready" panel moves the file into the library. Rationale: REC-003-R13 and the privacy review rely on nothing outliving the session unless the user acts; auto-keep would fill storage silently. Alternatives: keep every recording (rejected), a Settings switch "Keep recordings" (adds a key and a default; rejected).
- **REC-010-D2 Folder and storage category.** Decision: `Application Support/RecordingLibrary`, a new FILE-009 category "Saved recordings" that is not cleanable; the temporary `<tmp>/Recordings` category stays cleanable and reads "Unsaved recordings". Rationale: FILE-010 protects every non-cleanable category's roots automatically. Alternatives: reuse `.recordings` for both (Clear Caches would delete kept recordings; rejected), Documents (exposed in Files by `UIFileSharingEnabled`-style settings later; Application Support matches the other stores).
- **REC-010-D3 No index.** Decision: scan the folder (names, sizes, modification dates via resource values). Rationale: no state to drift from the files; at most a few dozen files of ≤ 10 minutes each. The modification date is a file timestamp inside the container (declared reason C617.1).
- **REC-010-D4 Facts from a header read.** Decision: `AVURLAsset` loads duration and the first video track's natural size, nominal frame rate and format description (codec four-character code). No video track, no duration or a load error → Incomplete. Rationale: `RecordedVideoInspector` reads every sample and QA-008 decodes audio; both are for tests and validation, not lists. Alternatives: QA-008 validator per row (rejected: seconds per file).
- **REC-010-D5 Thumbnails.** Decision: `AVAssetImageGenerator` (`appliesPreferredTrackTransform`, maximum 240 px, zero tolerance not required) at min(1 s, duration / 2), JPEG 0.7 in `Caches/RecordingThumbnails/<name>.<bytes>.jpg` plus an in-memory dictionary. Rationale: the cache is regenerable, so Clear Caches may remove it.
- **REC-010-D6 Share without a copy.** Decision: the library file itself is handed to the share sheet (REC-012's presenter and excluded activities). Rationale: REC-012 copies only to give a temporary file a stable descriptive name; a kept file already has its own name and stays where it is.
- **REC-010-D7 Rename rules.** Decision: trimmed, 1-100 characters, no "/" or ":", not starting with ".", unique (case-insensitive) in the folder; the old extension is kept. Errors: "Enter a name.", "Names can't contain / or :.", "Names can't start with a dot.", "Use at most 100 characters.", "A recording with that name exists."
- **REC-010-D8 Erase and backup.** Decision: FILE-011 category `recordings` ("Saved recordings", folder `RecordingLibrary`, count = non-hidden files). Not in the FILE-005 backup: recordings are large media the user can share; the backup's records stay as they are.
- **REC-010-D9 Announcements.** Decision: "Recording deleted.", "Recording renamed." and "Recording kept in Recordings." on the ACC-004 library lane; Keep also shows the recording notice.
