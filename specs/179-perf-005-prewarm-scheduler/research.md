# Research: PERF-005 Preset prewarm scheduler

- **PERF-005-D1 Where the core lives.** Decision: `PresentationLifecycle`. Rationale: pure Swift, no dependencies, Linux-tested in CI, already owns the presentation and memory-pressure protocols the scheduler follows. Alternatives: a new package (needs CI and project.yml changes for little gain); `Rendering` (not Linux-tested).
- **PERF-005-D2 Concurrency.** Decision: a lock-protected `@unchecked Sendable` class, not an actor or main-actor type. Rationale: loads finish on the executor's thread and must admit results without hopping to the main thread (S3); tests stay synchronous with a spy executor. Alternatives: an actor (every call from the main actor becomes async; harder to make suspension wait).
- **PERF-005-D3 Budget values.** Decision: physical memory < 4 GB → 48 MB; < 8 GB → 96 MB; otherwise 192 MB. Rationale: a 4032 × 3024 photo with mips is ~65 MB, so one typical picture fits everywhere; D1 and D3 (6 GB) get 96 MB, D2 192 MB. Alternatives: a fixed 64 MB (would refuse typical photos).
- **PERF-005-D4 Eviction.** Decision: never live keys; candidates have rank ≥ the incoming rank; least recently used first; if candidates cannot free enough, drop the incoming item and evict nothing. Rationale: the next cue's picture outranks the cue after it.
- **PERF-005-D5 Suspension and the GPU.** Decision: the loader's GPU step (texture upload and mip blit) runs inside `context.graphicsStep { }`, which refuses to start when the item is cancelled or the scheduler paused, and holds a gate lock that a presentation suspension takes after cancelling, so `suspend` returns only when no GPU step is running (PERF-011 rule "when this returns, no work is running" for GPU work). The CPU decode may finish later; its result is released.
- **PERF-005-D6 Presets.** Decision: `forwardPresets(ids) { … }` records the picks and calls the existing path synchronously; the `PresetWarmUpController` (2.5 s delay, suspension, PERF-006 steps) and `PresetPrewarmer` are not edited. Rationale: no frame-rate regression (SC-104 evidence on D1 stands).
- **PERF-005-D7 Photo adoption.** Decision: `ImageLayerSource.prewarmedTexture: ((URL) -> MTLTexture?)?`, consulted in `content`'s setter after MED-006's prepared slot. Rationale: covers every place the app sets content (new visual, refresh, slideshow) with one hook; the slideshow's own one-entry slot is untouched.
- **PERF-005-D8 What a scene's photo is.** Decision: for a scene whose visual is Photo, its slideshow's first slide when the scene restores a slideshow with slides, else the stored photo (MED-001 keeps one stored photo). Video and logo are modelled and skipped (spec Clarifications).
- **PERF-005-D9 Thermal.** Decision: pause at `ProcessInfo.ThermalState.serious` and `.critical` (the same states where PERF-003 reduces the glow); Low Power cuts the look-ahead to the next cue.
