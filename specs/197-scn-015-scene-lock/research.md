# Research: SCN-015 Scene Lock Mode

- **SCN-015-D1 Choke point.** Decision: `SceneLock.refusesEdit()` is the only place that decides and reports a refusal; each scene-writing coordinator API calls it first. The Settings-target write (`ParameterInspectorTargets.target(for:settings:)`) is the shared write path of the inspector, shelf, macros and snapshots, so one guard there covers all four even if a caller forgets. Rationale: the edits land in different stores (settings, scene carry, show file, history), so no single storage layer can refuse them without leaving live state diverged. Alternatives: refusing in SCN-002 autosave (rejected: the live output would change while the saved scene would not); UI-only disabling (rejected by the brief).
- **SCN-015-D2 Owner of the state.** Decision: `AppSettings.sceneLock` (a separate `@Observable` class created from the same defaults). Rationale: the targets, Settings and macros already receive `AppSettings`; adding a property avoids new parameters in shared signatures. Show and history get a `sceneLock` reference from AppCoordinator.
- **SCN-015-D3 Settings bindings.** Settings controls bind `AppSettings` properties directly; they are disabled (SwiftUI `.disabled`) while locked rather than guarded per property, because the cue apply path writes the same properties and must keep working.
- **SCN-015-D4 Unlock.** Decision: a confirmation dialog ("Unlock scene?" Unlock / Cancel). Alternative: long press (rejected: not discoverable for VoiceOver and Full Keyboard Access; a dialog works for every input).
- **SCN-015-D5 Announcements.** Lock/unlock and refusals go to the `library` lane of `AccessibilityAnnouncer` (ACC-004), the lane folder and snapshot messages use.
- **SCN-015-D6 Not edits.** Presets, cue navigation, scene switcher, blackout, tap tempo, pause, MIDI/OSC values and MIDI mappings (spec Clarifications).
