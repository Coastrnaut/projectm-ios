# Research: REC-002 Image Batch Export

- **REC-002-D1 — No live mutation instead of suspend/restore.** Decision: compute each image's values from `read` and the snapshot's recall plan and render offscreen; never call the snapshot coordinator's `write`. Rationale: SCN-009 must apply a side to the live output and therefore suspends autosave and history; the batch needs only pixels, so not touching live state is a stronger guarantee than suspending it, and it also works while the scene is locked. Alternatives: apply each snapshot live and grab REC-001 frames under SCN-009's suspend (visible flicker on the output, timing-dependent frames, refused while locked) — rejected.
- **REC-002-D2 — Renderer: the app's native generators, not QA-002's harness.** Decision: a small `SnapshotStillRenderer` built on `NativeSpectrumHost.makeGenerator` and FX-001's bloom chain. Rationale: snapshots hold the glow and spectrum parameters that only the native host draws (bloom is not a compositor layer); QA-002's `SceneRenderHarness` renders SCN-001 compositor stacks, lives in a test package and generates its photos from recipes. Its determinism rules are kept: fixed clock, seeded audio, warm-up frames. Alternatives: link `RenderGoldens` into the app (test-only package, no bloom, no native visuals) — rejected.
- **REC-002-D3 — Supported visuals.** Decision: the nine native visuals. projectM would need a second engine with its own EGL context (as `PresetPrewarmer` does) and a preset load per image; Camera, Photo, Video and Text need live media. Out of scope for this version; the sheet explains and Export is disabled.
- **REC-002-D4 — Determinism.** Decision: frames at t = 1 s + n/60 s, n = 0…3, the last one captured; bands from a fixed shape (a falling tilt with a SplitMix64-seeded ±15 % ripple, seed 0x52454332), the mono history a fixed two-sine mix, the stereo history the same pair with a quarter-period offset. Same inputs → same bytes (tested).
- **REC-002-D5 — Sizes.** Decision: REC-014's three fixed shapes at 1080 p: Landscape 1920 × 1080, Portrait 1080 × 1920, Square 1080 × 1080, chosen per export, not stored (no UserDefaults key).
- **REC-002-D6 — File names.** Decision: `<NN>-<safe name>.png` (rule in the spec). The 1-based position keeps names unique and in list order in any file browser; the case-insensitive collision suffix is a safety net.
- **REC-002-D7 — Where files live.** Decision: `<tmp>/SnapshotBatch/<UUID>/`, one folder per batch, removed on Done, on a new export, on cancel or failure, and (all leftovers) when the coordinator is created at launch — a directory listing only, as REC-012-R6.
- **REC-002-D8 — Offers.** Decision: Save… uses SwiftUI's multi-document `fileExporter` (the user picks a folder); Share… uses `UIActivityViewController` with every file URL and REC-012's excluded activities; Save to Photos uses REC-011's `PhotosSaveCoordinator` sequentially. DEBUG `-uitestShareSimulation` and `-uitestPhotosAccess` stand-ins work unchanged.
- **REC-002-D9 — Cancel.** Decision: a flag checked before each image; the current image finishes (at most one image of work), then the folder is deleted and nothing is offered.
