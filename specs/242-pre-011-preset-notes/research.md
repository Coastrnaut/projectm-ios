# Research: PRE-011 Preset Notes

- **PRE-011-D1 — Own file, not inside tags.json.** Decision: `PresetCollections/notes.json`, schema 1. Rationale: tags, overrides and smart collections each have their own file and backup record; a separate file keeps their formats, golden fixtures and older readers unchanged. Alternatives: a field in `tags.json` (a format change and a version bump for every tag reader); UserDefaults (notes would land in the preferences plist, which the privacy review lists, and FILE-005 settings policy).
- **PRE-011-D2 — Format and reading.** Decision: `{ "schemaVersion": 1, "notes": { "<preset ID>": "<text>" } }`; FILE-007 schema first (8 MiB, depth 3, strings up to 16 KiB, 20,000 elements, no duplicate keys); then the version: older → a migration table step (empty today, as PRE-008), current → read, newer → unavailable. The body is lenient like PRE-016: an entry that is not a string, empty after trimming, too long, or under an invalid ID is dropped and counted. Encoding is stable (sorted keys).
- **PRE-011-D3 — Length.** Decision: 2,000 characters counted as Swift `Character`s (grapheme clusters, what the user sees), and at most 8,000 UTF-8 bytes per stored string implied by the 16 KiB string limit. Alternatives: UTF-8 bytes (the count would disagree with what the user sees).
- **PRE-011-D4 — Diagnostics exclusion is structural.** Decision: no diagnostics path takes the notes store as input; `check_compliance.py` refuses `PresetNote`/`noteStore`/`notes.json` in diagnostics sources (Packages/Diagnostics, Apps/CaptureLab, the PERF-012 report files, Apps/projectM-iOS/Automation). An app test saves marker notes through the app's store, exports the PERF-012 report through the Export button's gathering path and encodes a diagnostics snapshot with frame timings through `DiagnosticsExporter`, and asserts no marker. Audit: the PERF-012 report gathers counters only; CaptureLab's export is a separate app with no preset data; `DiagnosticsLog` takes fixed messages and numbers; `AutomationRunner` reports timings and IDs it chose (DEBUG or automation builds only).
- **PRE-011-D5 — Backup and restore.** Decision: record `collections/notes.json` (no format version change, as PRE-003/PRE-016/PRE-008: no FILE-005 reader has shipped); records digest `preset-notes`; restore per preset ID: new → added (within the 20,000 limit), identical → kept, clash → Replace takes the backup's, Keep both and Skip keep the device's (one note per preset, so "both" cannot exist).
- **PRE-011-D6 — Search.** Decision: `PresetLibrary.search(tagMatches:)` gets the union of tag matches and note matches (folded substring over the note texts of listed presets). No new search API.
- **PRE-011-D7 — Integrity.** Decision: `PresetReferenceStore.notes` ("Notes", "Remove Note"), scanned after overrides; the safe fix removes the note through the store.
